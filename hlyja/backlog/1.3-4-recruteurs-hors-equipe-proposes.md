# Proposer dans le champ Recruteurs les noms hors équipe déjà saisis dans les dossiers

## Résumé
En mode serveur, le champ Recruteurs ne propose plus que les prénoms de l'équipe enregistrée dans la base. Un nom tapé à la main (une personne qui n'a pas de compte, un manager invité) reste dans le dossier, mais n'est plus proposé ailleurs ; avant la v1.3, le navigateur le gardait. C'est une petite régression de saisie, notée dans la doc produit ; proposer aussi les noms déjà présents dans les dossiers lus la comblerait sans rien stocker de plus.

## Priorité
**Basse** — gêne de saisie limitée (retaper un nom), régression acceptée et documentée ; aucune donnée perdue.

## Détail
### Proposition
En mode serveur, compléter la liste de `QUI.equipe()` avec les noms des champs `recruteurs` des dossiers déjà lus par la page (par exemple après `S.listCandidates()` sur `index.html`, et sur le dossier ouvert ailleurs), sans doublon avec l'équipe et sans écriture dans le navigateur ni dans l'API. Mettre à jour la règle « Recruteurs hors équipe » de `hlyja/doc/produit/stockage-partage.md` et la phrase de `docs/backend/MODELE.md` l. 41.
### Bénéfice
Pour les recruteurs : un nom extérieur saisi une fois est reproposé à toute l'équipe, comme les autres prénoms.
### Existant à réutiliser
`QUI.compte(moi, prenoms)` et `QUI.ajouter` (`assets/qui.js`) ; liste du champ Recruteurs (`assets/ui.js` l. 113, 172).
### Effort
S : fusion de deux listes à l'affichage, un cas e2e.
