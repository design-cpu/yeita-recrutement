# CONTRIBUER.md dit encore que les données restent dans le navigateur de chacun

## Résumé
Le guide de contribution, destiné à toute l'équipe, dit « Données fictives uniquement, tant que le stockage partagé n'est pas branché » et que les données « restent dans le navigateur de chacun ». Depuis la 1.3, le stockage partagé est branché sur `recrutement.yeita.fr`, et depuis la 1.4 le bandeau des pages dit que les candidatures sont sur le serveur de l'équipe. Le guide et l'outil se contredisent donc sur l'endroit où vivent les données et sur ce qui est permis d'y saisir. Il faut réécrire la phrase sur le stockage. L'utilisateur doit aussi décider si la règle « données fictives uniquement » est levée, gardée ou soumise à une condition.

## Priorité
**Moyenne** — contradiction, constatée, entre le guide de référence de l'équipe et le bandeau 1.4 sur l'endroit où sont stockées des données personnelles, à lever avant la première vraie candidature ; aucun bug du produit, d'où pas de priorité haute.

## Détail
### Constat
`CONTRIBUER.md` l. 7 : « **Données fictives uniquement**, tant que le stockage partagé n'est pas branché : depuis la version 1.1, l'espace est en ligne derrière la connexion Google @yeita.fr, mais les données restent dans le navigateur de chacun. Aucun nom, e-mail, téléphone ou CV de vrai candidat dans l'outil […] ». En mode serveur (règle « Mode serveur », 1.3, et règle « Bandeau jaune », 1.4, de `hlyja/doc/produit/stockage-partage.md`), les dossiers sont dans la base partagée. La condition « tant que le stockage partagé n'est pas branché » est remplie, mais l'interdiction reste écrite au présent.
### Risque si on ne fait rien
Deux lectures contraires pour l'équipe : selon le bandeau, l'outil sert à de vraies candidatures sur le serveur ; selon le guide, c'est interdit et tout reste local. Un contributeur peut aussi se tromper sur l'effet d'une saisie de test (écrite dans la base partagée, et non dans son navigateur).
### Piste
1. Décision de l'utilisateur sur « données fictives uniquement » dans l'outil en production : levée, gardée, ou levée sous condition (par exemple après la mise en service vérifiée de 1.2-1). Garder dans tous les cas l'interdiction de vraies données dans les tests, les captures et les commits.
2. Réécrire la l. 7 : le mode serveur sur `recrutement.yeita.fr` (base partagée, recruteurs connectés), le mode navigateur ailleurs ; renvoyer vers `hlyja/doc/produit/stockage-partage.md`.
Petite version express une fois la décision prise ; peut se faire avec 1.4-1 et 1.4-2.
