# Aucun test automatique du refus d'écraser une copie chiffrée existante

## Résumé
Chaque sauvegarde porte un nom à la seconde près, et le script refuse d'écraser une copie chiffrée qui porterait déjà ce nom. Cette règle protège les copies gardées sur le serveur, mais aucun test du dépôt ne la vérifie : elle n'a été vue qu'à la main, sur le banc. Une modification future du script pourrait la casser sans que la suite de tests le remarque.

## Priorité
**Basse** — aucun effet identifié à court terme : le comportement a été constaté correct en 1.7 (tâche 05, QA S10) et le code n'a pas changé à la reprise. Revue à la reprise (2026-10-28) : toujours juste, mentions de rclone et des pings retirées.

## Détail
### Constat
R8 de la spec 1.7 : « Un nom de `.db.age` déjà pris → échec, rien n'est écrasé. » Implémenté dans `deploy/backup.sh` (l. 114-117, nom tiré de `date -u +%Y-%m-%dT%H%M%SZ`, l. 97). `tools/test-sauvegarde.sh` ne contient aucun cas qui crée d'avance le `.db.age` attendu : il faudrait figer l'horloge.
### Risque si on ne fait rien
Une régression (écrasement d'une copie antérieure) passerait les 102 vérifications du lanceur (rapport de QA de la reprise).
### Piste
Dans `tools/test-sauvegarde.sh`, un faux `date` dans le `PATH` du cas (heure fixe), le `.db.age` de cette heure créé d'avance avec un contenu connu ; attendu : code 1, « … existe déjà : rien n'est écrasé. », fichier inchangé (empreinte), aucun clair restant, `sauvegarde-derniere.json` en `echec` à l'étape « chiffrement (age) », `sauvegarde-reussie.json` inchangé. Le lanceur ne tourne que dans un conteneur jetable (`BANC_JETABLE=oui`). Vérifier par une mutation (retirer le test d'existence) que le cas échoue.
