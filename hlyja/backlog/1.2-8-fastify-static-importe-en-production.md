# @fastify/static est chargé même en production

## Résumé
L'API ne sert les fichiers du site qu'en mode local (`DEV_STATIC`), mais elle importe le module `@fastify/static` à chaque démarrage, y compris en production. Le module n'est pas enregistré et ne sert rien ; il est seulement chargé en mémoire. Depuis la v1.3, l'API tourne dans une image Docker de production qui installe ce module (`npm ci --omit=dev`, `@fastify/static` étant une dépendance de production). Un import à la demande, avec le module en dépendance de développement, l'écarterait du code et de l'image de production.

## Priorité
**Basse** — sans effet constaté (la revue de code l'a classé facultatif) ; aucune route statique n'existe en production.

## Détail
### Constat
`api/src/app.js` l. 5 : `import fastifyStatic from "@fastify/static";` ; l. 85 : enregistré seulement `if (config.devStatic)`.
### Risque si on ne fait rien
Code chargé sans usage en production ; une faille du module ou de ses dépendances (`@fastify/send`) concernerait aussi un démarrage de production.
### Piste
Passer aussi `@fastify/static` en `devDependencies` (`api/package.json` l. 15) pour qu'il ne soit plus installé par `docker/api.Dockerfile` ; vérifier que `DEV_STATIC` sans le module donne un message clair.
`const { default: fastifyStatic } = await import("@fastify/static")` dans la branche `config.devStatic` (rendre la construction de l'app asynchrone si besoin). Rejouer `npm test` et la mutation « fichiers cachés ».
