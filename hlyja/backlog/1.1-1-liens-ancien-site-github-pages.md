# Les liens vers l'ancien site GitHub Pages mènent à une page 404

## Résumé
Les pages renvoient encore vers l'ancien site GitHub Pages (`leofuster-story.github.io/yeita-recrutement/`), qui répond aujourd'hui 404. Deux endroits sont touchés : le lien « Ouvrir sur le site », proposé à la place du bouton d'impression quand une page est ouverte dans l'artefact Claude, et la carte « Site du recrutement — GitHub Pages » de l'inventaire du guide. Un recruteur qui veut imprimer ou exporter en PDF depuis le hub tombe sur une erreur, et le guide publié sur `recrutement.yeita.fr` affiche un lien mort. La v1.1 a remplacé GitHub Pages par le serveur OVH sans toucher aux pages (hors périmètre).

## Priorité
**Moyenne** — lien mort reproduit (`curl` → 404), mais sur un parcours secondaire : l'impression depuis l'artefact Claude et un lien de l'inventaire, alors que le site lui-même imprime normalement.

## Détail
### Reproduire
1. Ouvrir une page imprimable (ex. la carte d'identité) dans l'artefact Claude : le bouton d'impression est masqué, la note propose « Ouvrir sur le site ».
2. Cliquer le lien, ou la ligne « Site du recrutement » de l'inventaire de `index.html`.
### Attendu
Le lien ouvre la même page sur `https://recrutement.yeita.fr/` (connexion Google pour les pages protégées).
### Observé
`https://leofuster-story.github.io/yeita-recrutement/…` → 404.
### Où
- `assets/yeita.js` l. 169-172 : commentaires « GitHub Pages » et `var SITE = "https://leofuster-story.github.io/yeita-recrutement/";` (utilisé l. 185 et exporté l. 216).
- `index.html` l. 431 : `site: {name:"Site du recrutement", sub:"GitHub Pages", …, href:YEITA.SITE, …}`.
Piste : `SITE = "https://recrutement.yeita.fr/"`, `sub:"recrutement.yeita.fr"`, commentaires mis à jour ; relancer `tools/e2e-liens.py`.
### Preuve
`curl -s -o /dev/null -w '%{http_code}' https://leofuster-story.github.io/yeita-recrutement/` → `404` (idem pour `/candidatures/` et `/assets/data-diamants.js`), le 2026-10-26.
