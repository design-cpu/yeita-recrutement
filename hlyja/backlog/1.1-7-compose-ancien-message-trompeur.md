# Avec un Docker Compose trop ancien, le déploiement s'arrête sur un message trompeur

## Résumé
`deploy.sh` lit les réglages avec `docker compose config --environment`, une option récente de Compose. Si le serveur OVH, dont on ne connaît pas encore la configuration, a une version plus ancienne, le script s'arrête avec « .env incomplet ? » alors que le `.env` est correct. L'arrêt est sûr (rien n'est touché), mais la personne qui déploie cherchera la panne au mauvais endroit.

## Priorité
**Basse** — sévérité mineure (arrêt sûr), constat de relecture non rejoué faute d'un Compose ancien sur le banc.

## Détail
### Reproduire
1. Sur une machine avec un Compose qui ne connaît pas `config --environment`, lancer `deploy/deploy.sh` avec un `.env` correct.
### Attendu
Un arrêt qui nomme la cause : « Docker Compose x.y est trop ancien : il faut au moins … ».
### Observé
« ARRÊT : Compose ne peut pas lire les réglages (.env incomplet ?). »
### Où
`deploy/deploy.sh` l. 38 ; `deploy/prepare-serveur.sh` l. 31 (ne vérifie que la présence de Compose) ; prérequis de `deploy/README.md`.
Piste : vérifier la version minimale de Compose dans `prepare-serveur.sh` et avant la lecture des réglages dans `deploy.sh` (ou tester l'option et afficher un message dédié), et l'écrire dans les prérequis du README.
### Preuve
Constat du relecteur (revérification sur `0f6b61f`, banc en Compose 2.40.3) ; non rejoué : il faudrait installer un Compose ancien sur le banc.
