# Code mort dans l'EC2 et libellés sans usage depuis le retrait de « Liens et outils »

## Résumé
La 1.10 a retiré l'encart « Liens et outils » des EC et l'ancien formulaire d'ajout d'un candidat. Le nettoyage a été fait pour l'EC1 et les styles, mais la page EC2 garde du code qui ne s'exécute plus, et huit libellés de `wording.fr.js` ne servent plus (ou seulement à ce code mort). Rien ne casse ; un lecteur du code croit ces éléments encore utilisés.

## Priorité
**Basse** — aucun effet visible ; la revue de code l'a laissé au backlog après avoir corrigé l'EC1, et le nettoyage par expression régulière de l'EC1 a montré qu'il faut le faire avec soin (régression N1).

## Détail
### Constat
- `candidatures/ec2.html` : `liens()` (l. 802 à 813) sort sur `if(!document.getElementById("liens-in")) return;` ; la page n'a plus d'élément `liens-in` (`grep -c 'id="liens-in"'` → `0`) : la suite de la fonction ne s'exécute jamais, dont le second `grille.href` (l. 812, déjà posé l. 807).
- `candidatures/ec2.html` l. 832 : garde `if(document.getElementById("cf-t"))`, élément absent de la page.
- `assets/wording.fr.js` : `ajout.plus`, `ajout.personneAide`, `recruteurs.aide` sans aucun usage ; `ec.viderQuestion`, `ec.viderTexte`, `ec.scorecard`, `ec.grille`, `ec.carte` utilisés seulement par le code mort ci-dessus (recherche dans `assets/` et `candidatures/`).
### Risque si on ne fait rien
Un futur changement des liens de l'EC2 modifie du code qui ne tourne pas ; des libellés morts sont traduits ou relus pour rien.
### Piste
Réduire `liens()` aux lignes 804 à 807 (icône de la grille), retirer la ligne 832, retirer les huit libellés après un dernier `grep` sur tout le dépôt ; rejouer `tools/e2e-parcours.py` et `tools/e2e-candidatures.py`, vérifier la carte d'identité (contrôle N1).
