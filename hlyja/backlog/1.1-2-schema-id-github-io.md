# L'identifiant du schéma du dossier candidat pointe vers un site GitHub Pages

## Résumé
Le schéma `docs/dossier-candidat.schema.json` se déclare avec l'adresse `https://yeichati.github.io/yeita-recrutement/…`, un site qui n'existe pas (404) et que le projet n'utilisera plus. Rien ne lit cette adresse aujourd'hui, mais un outil de validation qui voudrait la résoudre échouerait, et elle laisse croire à une publication sur GitHub Pages.

## Priorité
**Basse** — aucun effet identifié : aucun fichier du dépôt ne résout ce `$id`.

## Détail
### Constat
`docs/dossier-candidat.schema.json` l. 3 : `"$id": "https://yeichati.github.io/yeita-recrutement/docs/dossier-candidat.schema.json"`. L'adresse répond 404 (`curl`, 2026-10-26). `docs/` n'est pas publié (`SKIP` de `tools/build.py`), donc l'adresse ne peut pas non plus devenir `recrutement.yeita.fr/docs/…`.
### Risque si on ne fait rien
Une référence trompeuse de plus vers GitHub Pages ; échec d'un futur outil qui résoudrait le `$id`.
### Piste
Remplacer par un identifiant stable qui ne prétend pas être une adresse servie (ex. `urn:yeita:recrutement:dossier-candidat:v3`) ou par l'adresse du fichier dans le dépôt GitHub. À traiter avec 1.0-1 (même dossier `docs/`).
