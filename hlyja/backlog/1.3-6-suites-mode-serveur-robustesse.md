# Les suites de test du mode serveur s'arrêtent à la première exception et lancent l'API sans garde

## Résumé
Les deux suites ajoutées en v1.3 (`tools/test-serveur.js`, `tools/e2e-serveur.py`) détectent bien les défauts visés, mais elles sont fragiles : l'e2e lance l'API sur un port fixe sans vérifier qu'il est libre (elle pourrait jouer contre un autre serveur), son lancement n'est pas protégé par le `try` qui l'arrête, et son journal n'est jamais fermé ; les deux suites s'arrêtent à la première exception au lieu de compter les échecs suivants. Enfin l'envoi de départ n'est exercé que sous l'identité d'Alice (`DEV_EMAIL`), écart à R38 couvert à la main par la QA sur le banc Dex.

## Priorité
**Basse** — aucun faux résultat observé ; les échecs restent francs (QA S36, S38) ; l'envoi de départ sous une autre identité est vérifié à la main (QA S30).

## Détail
### Constat
- `tools/e2e-serveur.py` l. 15 : `PORT = int(os.environ.get("E2E_PORT", "18765"))` ; l. 32-36 : l'attente sur `api/sante` accepte la réponse de n'importe quel serveur déjà à l'écoute, sans `p.poll()` ; l. 73 : `proc = lancer_api(base)` avant le `try` (l. 74), donc ni arrêt ni nettoyage de `base` si le lancement échoue après `Popen` ; l. 30 : `journal = open(...)` jamais fermé.
- QA S38 : sous MT3, l'e2e s'arrête sur une exception Playwright (`Cannot read properties of null (reading 'dataset')`) au lieu de continuer ; `tools/test-serveur.js` l. 426 : `.catch(e => { console.error("FAIL exception", e); process.exit(1); })` termine toute la suite.
- Écart à R38 (`spec/spec-finale.md`) : `DEV_EMAIL` (Alice) pour les requêtes sans en-tête ; l'envoi de départ de Bob ou Léa n'est pas exercé par l'e2e (revue Q8).
### Risque si on ne fait rien
Un port occupé donne des résultats sur une autre API ; un processus `node` et un dossier temporaire restent après un échec de lancement ; une régression masquée derrière la première exception n'apparaît qu'au passage suivant.
### Piste
Choisir un port libre (socket liée au port 0) ou vérifier `p.poll() is None` avant chaque essai ; lancer l'API dans le `try` ; `with open(...)` pour le journal ; envelopper chaque scénario dans un `try` qui compte un FAIL et continue (les deux suites). Pour l'envoi de départ : garder CA8 sur le seul contexte d'Alice (proposition de la revue) et l'écrire dans `hlyja/technique/conventions.md`, l'essai sous Bob restant au guide de test.
